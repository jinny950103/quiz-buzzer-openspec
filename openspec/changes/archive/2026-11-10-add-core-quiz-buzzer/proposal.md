# Proposal

## Why

課堂搶答目前以紙本 Guided Notes（填空式學習單）進行：老師收回講義後，讓各組上台把答案寫在黑板上，流程耗時且難以判定先後。需要一個可在本機運作的線上搶答系統，讓老師匯入既有學習單、即時開放搶答，並把搶答成功的答案寫回原學習單，取代黑板流程。

本 change 建立系統的基本架構與期末專題要求的全部**核心功能**，作為後續額外功能（CSV 匯出、公平順位機制等）的基礎。

## What Changes

- 新增 Flask 單程序 Web 應用：老師頁面與學生頁面兩種角色入口，活動狀態存於程序記憶體。
- 老師可上傳 `.xlsx` 格式的 Guided Notes；系統依表頭（「題號」「作答」）動態定位題目與填空格，題數與學習單一致，題目以題號表示，不需匯入題目敘述。
- 支援單題（一題一個填空格）與題組（同一題號底下多個填空格，需一次一起送出）兩種題目結構。
- 老師可設定組別數量、開啟搶答、結束搶答；活動階段（準備中 → 搶答中 → 已結束）同步給所有使用者。
- 學生選擇組別後，於搶答中以組別為單位送出每一題的答案；每組每題只能送出一次。
- 每題以伺服器收到的先後順序判定，最先送出的組別為該題搶答成功者。
- 搶答結束前，學生只能看到自己組別的作答狀態；老師可即時檢視所有組別的作答狀況與目前結果。
- 搶答結束後，學生與老師可檢視每題的搶答結果與各組順位。
- 老師可將搶答成功的答案匯出回原 Guided Notes：保留原檔格式，答案寫入原題目的填空格，下載為新的 `.xlsx`。
- 不在本 change 範圍：匯出 CSV、公平搶答順位機制、帳號密碼登入、多台設備連線部署、資料持久化。

## Capabilities

### New Capabilities
- `guided-notes-io`: Guided Notes `.xlsx` 的匯入解析（動態定位題號、填空格、題組）與搶答答案匯出回原檔。
- `quiz-session`: 搶答活動的生命週期與角色：老師/學生入口、組別設定、階段切換（準備中/搶答中/已結束）及所有使用者的階段同步。
- `buzz-answering`: 學生以組別送出答案、先到先得的搶答判定、作答可見性規則，以及老師/學生的作答狀況與結果檢視。

### Modified Capabilities
（無，此為專案第一個 change）

## Impact

- 新增程式碼：`app/`（Flask 應用、服務層、Guided Notes 讀寫模組、模板與靜態檔）、`tests/`（pytest 與 Playwright 測試）。
- 新增相依套件：`flask`、`openpyxl`、`pytest`、`playwright`（列於 `requirements.txt`）。
- 新增 HTTP API：活動狀態查詢、匯入、開啟/結束搶答、送出答案、匯出等 JSON/檔案端點。
- 無外部服務、資料庫或機敏設定；僅於本機 `127.0.0.1` 執行。
